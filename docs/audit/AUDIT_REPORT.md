# Nova AI — Complete A-to-Z QA & Software Audit Report

**Audit Date:** 2026-11-08  
**Role:** Senior QA Engineer & Software Auditor  
**Audit Scope:** Full static code review (Phase 1), live headless browser UI & UX verification with 25 screenshots (Phase 2), and end-to-end functional/security/edge-case execution harness (Phase 3).  
**Safety Compliance:** All live execution was performed inside an isolated copy (`../nova-audit-copy`) using mocked LLM/gateway HTTP servers and harmless commands. Zero original project files in `d:\Developer Mode on\nova-ai` were modified.

---

## 1. Executive Summary

Nova AI has a well-designed zero-pip architecture and passes its existing **231 Python unit tests** (`21.86s`) and **6 Node.js voice regression tests**, with **0 syntax errors** across all 50 `.py` files (`python -m py_compile`) and all 4 project `.js` files (`node --check`).

However, our A-to-Z static and live runtime audit uncovered **45 distinct findings**:
- **5 Critical** (including a complete breakage of **"Save Settings"** in the UI returning `HTTP 400`, missing `global LAST_RUN_CODE_APPROVED_TIME` declarations breaking the `RUN_CODE` trust window, `NO_CONFIRM_TOOLS` omitting read-only/workspace tools and untrusted `GITHUB` calls, Python 3.8/3.9 import-time crashes, and incomplete PyInstaller packaging).
- **11 High** (including `[[PLAN]]` being a dummy no-op that never executes steps, `[[ORGANIZE]]` bypassing the workspace jail, `[[BROWSER_RESEARCH]]` allowing local `file:///` reads outside the workspace, `is_sensitive_nova_file()` omitting `memory.json`/`audit.jsonl`/`server.py`, and Audit Log UI misrendering `EXECUTED` status and `Guardian` verdicts).
- **16 Medium** (including `POST /api/chat` crashing with `500 AttributeError` on JSON arrays, `/api/chat/stream` corrupting SSE responses on `LLMError` and emitting wildcard CORS, `mask_secrets()` referencing undefined `CONFIG`, `GitHubConnector` extracting every zip file twice and calling non-existent `skills_engine.invalidate_cache()`, `diagnostics.py` misidentifying OpenAI/Anthropic keys as Google Gemini, and non-Windows platform bugs).
- **13 Low** (including invisible text on the `"☀️ Run Morning Briefing Now"` button due to undefined CSS variables `--c`/`--c2`, missing `[untrusted source]` badges in the Second Brain UI panel, `showToast("error")` playing the success chime, and multiple `README.md` vs. code discrepancies).

## 4. What PASSED (Verified Working)

1. **Zero Syntax Errors & Existing Test Suites**:
   - `python -m py_compile` passed on **50 / 50** Python files.
   - `node --check` passed on **4 / 4** project JavaScript files (`web/app.js`, `web/remote.js`, `web/qr.js`, `test_voice_regression.js`).
   - `python -m unittest discover -v -p "test_*.py"` passed **231 / 231** unit tests in `21.86s`.
   - `node test_voice_regression.js` passed **6 / 6** voice state-machine and barge-in tests.
2. **Authentication, Boot Exchange & CSRF / DNS-Rebinding Defenses**:
   - Visiting `/` without a cookie serves the locked page (`01_locked_page_no_cookie.png`).
   - One-time `/?boot=<code>` sets `HttpOnly; SameSite=Strict` `nova_session` cookie and stores `nova_token` in `sessionStorage`, then strips `?boot=` via `window.location.replace('/')`. Replaying the same boot code returns `403`.
   - Every `/api/*` request requires **both** the `nova_session` cookie and `X-Nova-Token` header (`secrets.compare_digest`), failing closed (`401`) if either is missing.
   - `check_local_request()` blocks non-localhost `Host` headers, mismatched ports, `Origin` headers from other ports, and `Sec-Fetch-Site: cross-site` / `same-site` (`403`).
3. **Mobile Remote Pairing (`:8766`) & Lockout**:
   - One-time 5-minute `?pair=<code>` exchanges for a per-device token, strips `?pair=` from the phone URL via `history.replaceState` (`25_remote_phone_ui_paired.png`), supports listing and revoking devices in the PC UI (`13_panel_mobile_remote.png`), and locks out an IP (`429`) after 5 failed authentication attempts.
4. **Taint Propagation & Provenance**:
   - External tools in `TAINT_SOURCE_TOOLS` taint the current turn; `REMEMBER` and `NOTE` in a tainted turn require user confirmation; approving via `/api/confirm`, Telegram (`/allow`), or Discord (`/allow`) preserves `tainted=1` in `data/memory.json` and SQLite `notes.tainted`; `build_system()` and `SEARCH_NOTES` wrap stored memories/notes in `<UNTRUSTED_MEMORY_DATA>` / `<UNTRUSTED_NOTES_DATA>` blocks with `[from an untrusted source]` labels.
5. **Gateway Long-Command Safety (`pc_only`)**:
   - Commands over 2,000 chars for `CMD`/`POWERSHELL`/`RUN_CODE` and tainted executable `WRITE_FILE`/`EDIT_FILE` are rejected immediately.
   - Approval messages exceeding Discord (`1950` chars) or Telegram (`4000` chars) limits are never truncated — instead they mark the pending action `pc_only=True` and send a short notice requiring approval on the PC.
6. **Smart Home SSRF & DNS Rebinding Protection**:
   - `is_allowed_smart_home_host()` resolves the hostname once, blocks loopback (`127.0.0.0/8`, `::1`), link-local/cloud metadata (`169.254.0.0/16`), public IPs, and Nova's configured ports (`8765`, `8766`, `cfg["port"]`, `cfg["remote_port"]`), and connects directly to the resolved IP with the original `Host` header.
7. **Storage, DPAPI & Multilingual Support**:
   - SQLite schema auto-migration (`tainted INTEGER DEFAULT 0`), 20-thread concurrent `save_note` writes, BM25 ranking, Windows CryptProtectData (`dpapi:`) round-trip encryption, and Bengali (`বাংলা`), Hindi (`हिंदी`), and Urdu (`اردو`) chat + BM25 search all passed.

## 5. What Could Not Be Tested (Hardware / Live External Dependencies)

1. **Physical Hardware Microphone & Speakers (Web Speech API Live Audio)**:
   - Headless Chromium in automated testing does not have a physical microphone or speakers attached. We verified the full voice state machine (`idle`, `listening`, `thinking`, `speaking`), wake-word matching (`"hey nova"`, `"jarvis"`, multilingual variants), TTS heartbeat watchdog, and barge-in cancellation via `node test_voice_regression.js` (6/6 passed) and UI state inspection, but physical acoustic echo cancellation and real-room microphone pickup require human testing with hardware audio.
2. **Live External Cloud APIs (Anthropic, OpenAI, Gemini, Telegram Bot API, Discord API, WhatsApp Web)**:
   - Per safety rules (*"Use NO real API keys, bot tokens or personal data"*), all LLM, Telegram, Discord, and GitHub API interactions were tested against local mock HTTP servers and unit mocks rather than live third-party cloud credentials.
3. **Destructive OS Actions (`shutdown`, `restart`, `empty_recycle_bin`, `format`, `del`)**:
   - Per safety rules (*"Never run destructive commands on this machine"*), destructive system actions and Guardian regex rails were verified via static analysis, mocked `subprocess.run` assertions, and Guardian allowlist/denylist unit tests without executing actual OS shutdowns or file deletions.
